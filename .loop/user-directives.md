# Codex 앱 사용자 수정 지시

이 문서는 사용자가 Codex 앱에서 전달한 최신 제품 수정 지시를 새 CLI 세션에 인계한다. 최신 미완료 지시가 현재 루프 범위 안에서 가장 높은 우선순위다. 지시를 반영한 뒤에도 기존 검증, 로컬 우선, 안전 경계와 실제 아이 관찰 근거 구분을 유지한다.

## 2026-08-24 — 어린이 학습 화면 시각 방향

- 상태: 활성
- 사용자 지시: `design/reference-kids-tracing-ui.png` 같은 UI·UX로 아이들이 쉽게 학습할 수 있는 화면을 만든다.
- 적용 화면: 현재 `ㄱ` 따라 쓰기 핵심 화면.
- 반드시 유지: 정확한 손글씨 입력과 판정, 한국어 음성 안내와 다시 듣기, 지우기, 오프라인 동작, 2340 × 1080 기준, 큰 실제 입력 영역.

- 원본 자산: `app/src/main/res/drawable-nodpi/limdo_gecko_guide.png`, `limdo_sunny_flower_background.png`를 사용한다. 참고 화면의 캐릭터와 장식을 직접 복사하지 않는다.
- 접근성: 글을 읽지 않아도 시작점, 진행 방향, 성공·재시도, 다시 듣기, 지우기, 비활성 동작을 알 수 있어야 한다. 보호자와 접근성 서비스를 위한 짧은 한글 설명은 유지한다.
- 범위 제한: 이번 루프에서 새 글자, 새 수업, 저장, 점수, 보상, 서버, 로그인, 분석, 광고, 민감 권한을 추가하지 않는다.
- 전달 방식: 앞으로 새 수정 지시는 Codex 앱에서 전달하며 앱 작업자가 이 문서와 현재 루프 목표에 한글로 반영한다.

## 2026-08-24 — 교육용 한글 비율과 큰 양방향 입력 면적

- 상태: 활성, 이전 고정 `ㄱ` 가로 1170 px 기준을 대체하는 최우선 지시
- 사용자 지시: 입력 영역만 넓히거나 글자를 가로로 늘이지 않는다. 교육 목적에 맞게 실제 한글과 같은 비율·모양을 유지하고, 굵은 폰트처럼 가로와 세로 모두 넓은 입력 통로를 제공한다.
- 현재 문제: 2340 × 1080 화면의 `ㄱ`은 약 1491 × 620 px로 가로/세로 비가 약 2.41이라 자연스러운 한글 글자꼴보다 지나치게 가로로 늘어났다.
- 유지 기준: 실제 손가락 입력 Canvas는 최소 1872 × 648 px이고 화면에서 가장 큰 아이 상호작용 영역으로 유지한다.
- 글자 기준: 글자별 정규화된 교육용 template을 정사각형 em 안에 정의하고 x축·y축 동일 배율로 확대한다. 현재 `ㄱ`의 실제 bounds는 가로·세로 각각 최소 580 px이고 Canvas 높이의 75% 이상을 사용한다.
- 굵기 기준: 목표 획은 em의 12~18% 굵기로 보여 손가락이 지나갈 수 있는 넓은 통로가 되며, 입력 허용 폭과 시각 guide가 같은 geometry에서 파생된다.
- 조합 글자 기준: 이후 `가`는 자음 `ㄱ`과 모음 `ㅏ`의 상대 위치와 비율을 하나의 정사각형 em 안에서 보존한다. 이번 루프는 새 수업 화면을 추가하지 않고 geometry 계약과 테스트 fixture까지만 준비할 수 있다.
- 검증: 표시 경로와 판정 경로의 균일 배율, 글자 bounds, 획 굵기, 중심 정렬을 단위 테스트와 정확한 2340 × 1080 초기·재시도·성공 화면에서 실측한다.

## 2026-08-24 — 참고 화면 수준의 더 굵은 한글 획

- 상태: 활성, 기존 굵기 기준을 대체하는 최신 최우선 지시
- 사용자 지시: 첨부 참고 이미지처럼 화면 중앙 한글의 획 굵기를 현재보다 더 크게 만든다.
- 참고 이미지: `/Users/lim/Desktop/스크린샷 2026-08-24 오후 2.40.44.png`. 이미지는 굵고 넓은 흰색 쓰기 길의 시각 밀도만 참고하며 캐릭터·상표·배치는 복제하지 않는다.
- 현재 기준과 목표: 현재 `WritingCanvasGeometry`의 guide는 정사각형 em의 15%로, 2340 × 1080의 실제 Canvas에서 약 93 px이다. 우선 em의 20%인 약 124 px로 확대해 기존보다 약 33% 굵게 보이게 한다. 실제 화면 비교에서 참고 이미지의 굵은 쓰기 길보다 여전히 명확히 가늘면 20~22% 안에서 최소 추가 조정할 수 있다.
- 반드시 유지: `ㄱ` 중심선, 가로·세로 길이, 정사각형 em, 균일 x/y 배율, 화면 중앙 정렬, 시작점·방향 화살표·끝점의 의미를 바꾸지 않는다. 글자를 가로 또는 세로 한쪽으로 늘려 굵게 보이게 하지 않는다.
- 입력 판정: 시각 guide만 굵히되 아이의 기존 입력 허용 폭을 좁히지 않는다. 표시와 판정은 계속 같은 `WritingCanvasGeometry` 중심선에서 파생하며, 굵기 변경 때문에 기존 정상 입력·155/156 px 되돌림 경계가 역전되지 않도록 회귀 검증한다.
- 아이 관점: 흰색 쓰기 길이 노란 배경에서 한눈에 가장 큰 과제로 보여야 하고, 손가락으로 따라갈 수 있는 넓은 통로로 인식되어야 한다. 시작점·방향·끝점 표시는 굵어진 획에 묻히지 않아야 한다.
- 검증: 정확한 앱 2340 × 1080에서 초기·진행 중·재시도·성공 화면을 새로 캡처하고 guide 굵기를 픽셀과 em 비율로 실측한다. 참고 이미지와 현재 화면을 같은 상태로 비교하고, `./scripts/verify.sh`, `git diff --check`, 정상 입력 및 경계 회귀를 통과한다.
- 실제 아이 관찰: 자동·에뮬레이터·아이 대리 QA와 구분하며 실제 아이가 사용하지 않았다면 수행했다고 기록하지 않는다.

## 2026-08-24 — 정사각형 학습판·동적 획 안내·자동차 맞춤 보상

- 상태: 활성, 이전 동물 안내와 정적인 화살표 지시를 대체하는 최신 최우선 지시
- 사용자 지시: 쓰기 방향 화살표를 아이가 움직임만 보고 이해할 수 있는 동적 guide로 바꾸고, 화면의 보이는 학습판은 직사각형이 아닌 정사각형으로 실제 한글 쓰기 규격과 일치시킨다. 동물보다 자동차를 좋아하는 아이에 맞춰 경찰차·소방차·구급차·스포츠카와 다양한 자동차를 같은 그림체로 생성·적용하고, 정답이면 자동차가 해당 글자의 실제 획수만큼 이동하는 보상을 보여 준다.
- 정사각형 학습판: 손가락 입력을 받는 전체 Canvas는 기존 최소 1872 × 648 px와 화면 최대 상호작용 영역 계약을 유지한다. 다만 아이가 눈으로 보는 점선 중심축·학습판은 Canvas 짧은 변을 기준으로 한 정사각형으로 중앙 정렬한다. 정사각형을 만들기 위해 글자나 판정 경로를 비균일 배율로 늘이거나 줄이지 않는다.
- geometry 단일 진실: 보이는 정사각형 학습판, 교육용 글자 template, 동적 안내 위치, 아이 획 진행률, `GieokTraceEvaluator` 판정은 같은 정사각형 em과 균일 x/y 배율에서 파생한다. 현재 `ㄱ`과 향후 `가`의 자모 배치·횡종 비율을 각각 새 픽셀 실측과 단위 테스트로 고정한다.
- 동적 guide: 입력 전에는 첫 획의 시작→방향→끝을 큰 움직임으로 반복 시범하고, 입력 중에는 현재 획의 손가락보다 조금 앞쪽에서 다음 방향만 짧게 움직인다. 완료한 구간의 화살표는 사라지거나 약해지고 다음 획 안내만 활성화한다. 아이가 화면 문장을 읽지 않아도 시범만 보고 시작점과 진행 방향을 알아야 한다.
- 동적 화살표 명확성: 위치만 보여 주는 원·점 하나를 최종 동적 화살표로 간주하지 않는다. 움직이는 표식에는 현재 구간을 가리키는 오른쪽 또는 아래쪽 화살촉·방향성이 있어야 하고, 꼭지를 지나면 방향이 오른쪽에서 아래로 바뀌는 장면을 새 연속 프레임으로 확인한다. 원·링을 보조 강조로 함께 쓸 수는 있지만 방향 화살표를 대체할 수 없다.
- 동작 안전: 동적 안내는 시작점·글자 guide·아이 획·끝점·자동차를 가리지 않고, 입력 좌표를 가로채지 않으며, 앱이 배경으로 가거나 화면이 초기화되면 중단·복원된다. 성공·재시도·지우기·다시 듣기 상태에서는 서로 모순되는 애니메이션이나 음성이 동시에 나오지 않는다.
- 자동차 자산: 경찰차, 소방차, 구급차, 스포츠카, 택시, 버스, 쓰레기차, 화물트럭, 지게차의 9종을 우선 적용한다. 모든 차량은 오른쪽을 향한 둥근 유아용 2D 그림체, 굵고 일정한 외곽선, 밝은 고대비 색, 큰 표정, 글자·번호·브랜드 없는 투명 PNG로 통일한다. 동물 안내 이미지는 자동차 적용 뒤 기본 화면에서 제거하되 삭제하지 않고 회귀 근거를 보존한다.
- 자동차 선택·순환: 새 설정 화면이나 읽기 텍스트에 의존하지 않는다. 첫 적용은 경찰차를 기본 안내차로 사용하고, 이후 수업 또는 성공 흐름에서 9종이 예측 가능한 순서로 순환하도록 한다. 같은 세션의 지우기·재시도에서는 선택 차량이 임의로 바뀌지 않는다.
- 획수 이동 보상: 글자 lesson data에 실제 교육용 `strokeCount`를 명시하고, 정답 한 번마다 활성 자동차가 정확히 `strokeCount`칸 이동한다. 현재 `ㄱ`은 1획이므로 성공 시 1칸만 이동한다. 향후 다획 글자는 한 번에 건너뛰지 않고 획수만큼 짧고 분명한 이동을 순서대로 보여 준다. 실패·지우기·다시 듣기는 이동시키지 않고, 같은 성공 callback의 중복 이동을 금지한다.
- 보상 배치: 이동 경로와 자동차는 쓰기 정사각형 밖의 안전 영역에 두거나 guide를 가리지 않는 별도 레이어로 둔다. 아이가 결과를 바로 연결하도록 성공 `★ ✓`와 음성 시작 뒤 자동차가 움직이며, 이동 완료 전 새 입력을 받아 상태가 꼬이지 않게 한다.
- 구현 순서: 현재 활성 루프를 정상 완료한 다음 새 번호 루프를 만들어 ① 정사각형 학습판과 geometry 실측 ② 동적 획 안내 ③ 경찰차 기본 적용과 동물 교체 ④ 9종 자동차 순환 ⑤ `strokeCount` 기반 이동 보상을 각각 하나의 좁은 가설로 구현·검증한다. 한 반복에 여러 제품 변경을 묶지 않는다.
- 검증: 매 루프에서 정확한 앱 2340 × 1080 화면·hierarchy와 필요한 연속 영상 또는 프레임을 새로 수집한다. 정사각형 학습판의 가로·세로 동일 픽셀, 전체 입력 Canvas 최소 크기, 균일 em, 자동차 가림 없음, 동적 안내의 올바른 획 순서, `ㄱ` 성공 1칸·실패 0칸·중복 callback 0칸을 자동 테스트와 에뮬레이터 근거로 확인한다.
- QA 경계: 글을 읽지 못하지만 한국어를 들을 수 있는 다섯 살 아이의 대리 관점에서 시범·모양·위치·움직임·검증된 음성만으로 이해 가능성을 평가한다. 실제 아이가 직접 사용하지 않았다면 실제 아이 관찰로 표현하지 않는다.
- 이미지 생성 방식: Codex 내장 이미지 생성으로 만든 원본을 사용하며, 앱에 넣는 최종본은 실제 알파 채널과 투명 모서리를 검사하고 Android `drawable-nodpi`에 저장한다. 흰색·회색 체크무늬가 픽셀에 포함된 결과, 어두운 배경, 글자·상표·워터마크가 있는 결과는 사용하지 않는다.

## 2026-08-25 — 무의미한 작업 금지와 제품 진전 우선

- 상태: 활성, 모든 자동 전환보다 우선
- 사용자 지시: 의미없는 작업은 하지 않도록 자동화를 설정한다.
- 금지: 같은 화면·callback·동작에서 반복 횟수나 상한만 `N+1`로 바꾸는 루프, 이미 통과한 근거의 재수집, 제품 코드·판정·아이 경험에 새 판단을 주지 않는 작업을 만들거나 실행하지 않는다.
- 현재 판단: 루프 116에서 동일 안내 흐름을 53/52회까지 확인했으므로 내구성 근거는 충분하다. 쉰네번째 재생만 추가하는 기존 루프 117은 중복으로 종료한다.
- 전환 순서: 근거 있는 새 불편 → 최신 미완료 사용자 제품 지시 → 장기 한글 학습 목표의 다음 제품 단계 순으로 하나를 선택한다. 모두 없으면 큐를 비우고 `IDLE`로 종료한다.
- 다음 제품 단계: 테스트 fixture에 머문 `가` geometry를 production 계약으로 전환하고, 이후 표시·동적 획 안내·판정을 각각 검증 가능한 좁은 루프로 연결한다.
- 기계 차단: 모든 목표는 작업 가치 관문을 작성하고 감독자가 매 새 세션 직전에 검사한다. 문구만 꾸며 통과시키지 않으며 중복 목표는 실행하지 않는다.

## 2026-08-26 — 한글 교육 순서 정정

- 상태: 활성, 바로 앞 교육 순서를 대체하는 최신 지시
- 사용자 지시: 자음 다음 모음이며, 조합 글자는 `가 → 나 → 다` 순서가 기본이다. 한글 교육을 공식 자료로 조사하고 이후 작업이 참고할 수 있게 문서화한다.

- 코드·문서: `KoreanCurriculum.educationFlow`와 `docs/한글-교육-순서-근거.md`에서 이후 확장 순서를 고정한다.
