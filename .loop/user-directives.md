# Codex 앱 사용자 수정 지시

이 문서는 사용자가 Codex 앱에서 전달한 최신 제품 수정 지시를 새 CLI 세션에 인계한다. 최신 미완료 지시가 현재 루프 범위 안에서 가장 높은 우선순위다. 지시를 반영한 뒤에도 기존 검증, 로컬 우선, 안전 경계와 실제 아이 관찰 근거 구분을 유지한다.

## 2026-08-24 — 어린이 학습 화면 시각 방향

- 상태: 활성
- 사용자 지시: `design/reference-kids-tracing-ui.png` 같은 UI·UX로 아이들이 쉽게 학습할 수 있는 화면을 만든다.
- 적용 화면: 현재 `ㄱ` 따라 쓰기 핵심 화면.
- 반드시 유지: 정확한 손글씨 입력과 판정, 한국어 음성 안내와 다시 듣기, 지우기, 오프라인 동작, 2340 × 1080 기준, 큰 실제 입력 영역.
- 시각 기준: 밝고 따뜻한 노란 배경, 장식은 낮은 대비, 화면 중앙의 아주 큰 흰색 `ㄱ` 쓰기 길, 시작점의 독창적인 동물 안내 캐릭터, 끝점 목표, 가장자리의 크고 단순한 조작 버튼, 최소한의 읽기 의존성.
- 원본 자산: `app/src/main/res/drawable-nodpi/limdo_gecko_guide.png`, `limdo_sunny_flower_background.png`를 사용한다. 참고 화면의 캐릭터와 장식을 직접 복사하지 않는다.
- 접근성: 글을 읽지 않아도 시작점, 진행 방향, 성공·재시도, 다시 듣기, 지우기, 비활성 동작을 알 수 있어야 한다. 보호자와 접근성 서비스를 위한 짧은 한글 설명은 유지한다.
- 범위 제한: 이번 루프에서 새 글자, 새 수업, 저장, 점수, 보상, 서버, 로그인, 분석, 광고, 민감 권한을 추가하지 않는다.
- 전달 방식: 앞으로 새 수정 지시는 Codex 앱에서 전달하며 앱 작업자가 이 문서와 현재 루프 목표에 한글로 반영한다.

## 참고 이미지의 역할과 제한

- 참고 이미지는 밝은 색감, 중앙 집중형 쓰기 과제, 캐릭터가 획 방향을 보여 주는 구조와 큰 가장자리 버튼의 시각 기준이다.
- 참고 이미지의 상표, 로고, 정확한 캐릭터, 과일 그림, 배치를 그대로 복제하지 않는다.
- 실제 Android 구현은 LimDo의 기존 기능과 접근성 계약에 맞게 재구성한다.

## 2026-08-24 — 실제 글자 쓰기 폭 확대

- 상태: 활성, 이전 시각 방향보다 우선
- 사용자 지시: 입력 넓이가 아이들에게 너무 좁으므로 참고 이미지처럼 넓게 만들어 쉽게 글자를 쓰게 한다.
- 측정 기준: 2340 × 1080에서 실제 손가락 입력 내부는 최소 1872 × 648 px이다.
- 핵심 보정: 빈 Canvas만 넓히지 않는다. 실제 보이는 동시에 판정에 사용하는 `ㄱ` 가로 획은 최소 1170 px, 세로 획은 최소 540 px로 확대한다.
- 구현 경계: 화면에 보이는 목표 길과 `GieokTraceEvaluator`가 판정하는 경로는 같은 geometry를 사용해야 한다.
- 배치: 다시 듣기, 지우기, 비활성 다음 동작은 쓰기 길을 침범하지 않도록 가장자리 또는 하단 안전 영역에 둔다.
- 검증: 새 APK의 초기·재시도·성공 화면에서 입력 내부 bounds와 목표 가로·세로 획을 각각 실측한다.

## 2026-08-24 — 교육용 한글 비율과 큰 양방향 입력 면적

- 상태: 활성, 이전 고정 `ㄱ` 가로 1170 px 기준을 대체하는 최우선 지시
- 사용자 지시: 입력 영역만 넓히거나 글자를 가로로 늘이지 않는다. 교육 목적에 맞게 실제 한글과 같은 비율·모양을 유지하고, 굵은 폰트처럼 가로와 세로 모두 넓은 입력 통로를 제공한다.
- 현재 문제: 2340 × 1080 화면의 `ㄱ`은 약 1491 × 620 px로 가로/세로 비가 약 2.41이라 자연스러운 한글 글자꼴보다 지나치게 가로로 늘어났다.
- 유지 기준: 실제 손가락 입력 Canvas는 최소 1872 × 648 px이고 화면에서 가장 큰 아이 상호작용 영역으로 유지한다.
- 글자 기준: 글자별 정규화된 교육용 template을 정사각형 em 안에 정의하고 x축·y축 동일 배율로 확대한다. 현재 `ㄱ`의 실제 bounds는 가로·세로 각각 최소 580 px이고 Canvas 높이의 75% 이상을 사용한다.
- 굵기 기준: 목표 획은 em의 12~18% 굵기로 보여 손가락이 지나갈 수 있는 넓은 통로가 되며, 입력 허용 폭과 시각 guide가 같은 geometry에서 파생된다.
- 조합 글자 기준: 이후 `가`는 자음 `ㄱ`과 모음 `ㅏ`의 상대 위치와 비율을 하나의 정사각형 em 안에서 보존한다. 이번 루프는 새 수업 화면을 추가하지 않고 geometry 계약과 테스트 fixture까지만 준비할 수 있다.
- 검증: 표시 경로와 판정 경로의 균일 배율, 글자 bounds, 획 굵기, 중심 정렬을 단위 테스트와 정확한 2340 × 1080 초기·재시도·성공 화면에서 실측한다.

## 2026-08-24 — 참고 화면 수준의 더 굵은 한글 획

- 상태: 활성, 기존 굵기 기준을 대체하는 최신 최우선 지시
- 사용자 지시: 첨부 참고 이미지처럼 화면 중앙 한글의 획 굵기를 현재보다 더 크게 만든다.
- 참고 이미지: `/Users/lim/Desktop/스크린샷 2026-08-24 오후 2.40.44.png`. 이미지는 굵고 넓은 흰색 쓰기 길의 시각 밀도만 참고하며 캐릭터·상표·배치는 복제하지 않는다.
- 현재 기준과 목표: 현재 `WritingCanvasGeometry`의 guide는 정사각형 em의 15%로, 2340 × 1080의 실제 Canvas에서 약 93 px이다. 우선 em의 20%인 약 124 px로 확대해 기존보다 약 33% 굵게 보이게 한다. 실제 화면 비교에서 참고 이미지의 굵은 쓰기 길보다 여전히 명확히 가늘면 20~22% 안에서 최소 추가 조정할 수 있다.
- 반드시 유지: `ㄱ` 중심선, 가로·세로 길이, 정사각형 em, 균일 x/y 배율, 화면 중앙 정렬, 시작점·방향 화살표·끝점의 의미를 바꾸지 않는다. 글자를 가로 또는 세로 한쪽으로 늘려 굵게 보이게 하지 않는다.
- 입력 판정: 시각 guide만 굵히되 아이의 기존 입력 허용 폭을 좁히지 않는다. 표시와 판정은 계속 같은 `WritingCanvasGeometry` 중심선에서 파생하며, 굵기 변경 때문에 기존 정상 입력·155/156 px 되돌림 경계가 역전되지 않도록 회귀 검증한다.
- 아이 관점: 흰색 쓰기 길이 노란 배경에서 한눈에 가장 큰 과제로 보여야 하고, 손가락으로 따라갈 수 있는 넓은 통로로 인식되어야 한다. 시작점·방향·끝점 표시는 굵어진 획에 묻히지 않아야 한다.
- 검증: 정확한 앱 2340 × 1080에서 초기·진행 중·재시도·성공 화면을 새로 캡처하고 guide 굵기를 픽셀과 em 비율로 실측한다. 참고 이미지와 현재 화면을 같은 상태로 비교하고, `./scripts/verify.sh`, `git diff --check`, 정상 입력 및 경계 회귀를 통과한다.
- 실제 아이 관찰: 자동·에뮬레이터·아이 대리 QA와 구분하며 실제 아이가 사용하지 않았다면 수행했다고 기록하지 않는다.
