# 현재 루프 상태

루프: 049 — 회복 성공 지우기 뒤 정상 재입력 QA

상태: 준비

반복: 0

마지막 검증: 루프 048 반복 1에서 물리 1080 × 2340, 앱 2340 × 1080, `user_rotation=1`의 수정 APK로 앱 데이터를 한 번만 초기화했다. 첫 세 정상 입력의 `SUCCESS` 시작 직후 지우기가 각각 `준비 완료`로 취소됐고, 네 번째 정상 입력은 `SUCCESS` 시작→완료 한 회로 끝났다. 완료 뒤 지우기 한 번은 중복 완료 토큰 없이 `준비 완료`로 전환했고 4초 뒤 최초 초기 화면과 픽셀 해시가 같았다. `./scripts/verify.sh`와 `git diff --check`가 통과했다.

완료한 조건: 루프 048 성공 조건 1~8 전체. `SpeechPlaybackTracker.stop()`이 완료 상태도 `Ready`로 전환하도록 최소 보정했고 회귀 테스트를 추가했다. Canvas 1962 × 775 px, 버튼 373 × 168 px와 간격 37 px를 유지했으며 `아이 대리 점검: 통과`, `실제 아이 관찰: 실행 안 함`을 기록했다.

현재 실패: 최종 지우기로 초기 상태에 복원된 직후 추가 초기화나 지우기 없이 다섯 번째 정상 입력이 성공 완료로 회복하는지 새 근거로 확인하지 않았다.

현재 가설: 세 번의 즉시 지우기와 네 번째 성공 완료·지우기 뒤 다섯 번째 정상 중심선을 입력하면 이전 callback의 개입 없이 한 번의 `SUCCESS` 완료로 회복할 것이다.

다음 작업: 정확한 2340 × 1080에서 루프 048 흐름을 재현한 직후 다섯 번째 정상 입력의 성공 화면·callback과 3초 이상 안정 상태를 확인한다.

남은 조건: 루프 049 성공 조건 1~8 전체.
