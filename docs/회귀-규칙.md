# LimDo 회귀 규칙

## 목적

같은 사용자 지적 또는 같은 근본 원인이 두 번 나타났을 때 말로만 주의하지 않고 제품 규칙과 기계 검사로 승격한다. 이 문서는 이력 요약이 아니라 앞으로 모든 새 세션이 지켜야 할 재발 방지 계약이다.

## 승격 절차

1. `.loop/history.md`와 `.loop/user-directives.md`에서 같은 현상의 독립 근거가 두 번인지 확인한다.
2. 아이에게 미치는 영향과 공통 근본 원인을 한 문장씩 적는다.
3. 피해야 할 구현이 아니라 지켜야 할 제품 규칙을 적고 `왜`를 함께 기록한다.
4. 좌표·크기·순서·상태처럼 측정 가능하면 단위 테스트 또는 자동화 검사로 만든다.
5. 화면 품질이면 정확한 2340 × 1080 새 이미지·hierarchy의 판정 방법을 고정한다.
6. 검사 이름과 처음 통과한 루프를 아래 표에 연결한다.

## 현재 규칙

| 반복된 문제 | 제품 규칙과 이유 | 기계·시각 검사 |
| --- | --- | --- |
| 의미 없는 동일 QA 반복 | 이미 통과한 화면·callback의 횟수만 늘리지 않는다. 제품 판단이 달라지지 않는데 비용과 시간이 계속 들기 때문이다. | `scripts/check-work-value.sh`, `LOOP_GOAL.md` 작업 가치 관문 |
| 한글 자형·비율 불일치 | 표시·안내·판정은 같은 정사각형 em과 균일 배율을 쓴다. 다른 경로를 쓰면 아이가 본 모양과 입력 성공 조건이 달라지기 때문이다. | `KoreanCurriculumTest`, guide 외곽·비율·방향 계약, 정확한 화면 |
| 쓰기 영역이 좁거나 주변 UI가 공간을 차지함 | 실제 WritingCanvas는 2340 × 1080에서 최소 1872 × 648 px이고 가장 큰 상호작용 영역이어야 한다. 다섯 살 아이의 손가락 오차를 받아야 하기 때문이다. | `QA_CHECKLIST.md`, hierarchy bounds 측정 |
| 다른 앱이 공용 에뮬레이터 전면을 가져감 | 매 입력·캡처 전에 현재 focus와 glyph 관문을 확인하고 다른 프로젝트가 사용 중이면 조작을 중지한다. 다른 앱에 입력한 화면은 LimDo 근거가 아니기 때문이다. | `mCurrentFocus`·`mFocusedApp`, 현재 glyph·성공 hierarchy 관문 |
| `ㅅ·ㅈ·ㅊ` 자형과 동적 안내 경로 불일치 | 여섯 글자 `ㅅ·ㅈ·ㅊ·사·자·차`는 첨부 교육 기준의 초성 template을 공유하며 현재 획의 동일 크기 원형 점선·동적 표식·시작·끝점·입력 판정은 production geometry 하나에서 계산한다. `ㅅ`은 위 중앙에서 내려와 왼쪽으로 휘는 1획과 중앙 접합부에서 오른쪽으로 갈라지는 2획, `ㅈ·ㅊ` 몸체는 가로 뒤 중앙 접합부를 지나 왼쪽으로 휘는 연결 획과 접합부에서 갈라지는 오른쪽 획을 쓴다. 처음 배우는 아이에게 보이는 모양과 성공 조건이 다르면 잘못된 자형과 획순을 학습하기 때문이다. | `KoreanCurriculumTest` 공유 곡선 좌표·접합부 포함·현재 획 노출·원 크기와 간격·정역방향 판정, 첨부 이미지와 정확한 2340 × 1080 대표 화면 비교 |
| `ㅈ·ㅊ` 몸체의 반복된 과도한 굴곡 | `ㅈ·자` 몸체 첫 획은 윗가로 시작·끝, 중앙 접합부, 왼쪽 아래 끝의 네 점만 사용하고 오른쪽 획은 접합부·오른쪽 아래 끝의 두 점만 사용한다. `ㅊ·차`는 짧은 윗가로 뒤 같은 몸체를 공유한다. 교육용 중심선에 시각 효과용 중간 점을 여러 개 넣으면 두꺼운 선에서 굴곡이 증폭돼 아이가 다른 자형으로 인식할 수 있기 때문이다. | `KoreanCurriculumTest.siotJieutChieutFamiliesShareConnectedStrokeDirectionAndJudgmentContract`, 실제 2340 × 1080 `ㅈ·ㅊ` 화면 비교 |

새 규칙은 기존 행을 삭제하지 않고 추가한다. 근거가 한 번뿐이거나 원인이 다른 문제를 억지로 같은 규칙으로 묶지 않는다.
