# LimDo 1차 목표 작업 기획서

## 목표

다섯 살 아이가 한글 문장을 읽지 못해도 첫 화면에서 `자음`, `모음`, `가나다`의 세 가지 기본 학습을 구분하고, 원하는 학습을 골라 큰 쓰기판에서 따라 쓴 뒤 성공·재시도·다음 학습·홈 복귀까지 혼자 이해할 수 있는 로컬 Android 앱을 만든다.

1차 목표는 기능만 연결한 임시 화면이 아니다. 세 메뉴와 학습 화면 전체에 하나의 유아용 시각 언어를 적용하고, 즐겁지만 학습을 방해하지 않는 화려한 연출까지 구현한 뒤 디자인 팀 관문, QA 팀 관문, 다섯 살 아이 대리 시뮬레이션을 모두 통과해야 완료한다.

## 1차 제공 범위

### 첫 화면의 기본 세 메뉴

1. `자음`: 큰 대표 자음 모양과 고유 색을 가진 카드에서 자음 학습으로 들어간다.
2. `모음`: 큰 대표 모음 모양과 자음 카드와 구분되는 고유 색을 가진 카드에서 모음 학습으로 들어간다.
3. `가나다`: 자음과 모음이 합쳐지는 모습을 보여 주는 카드에서 `가·나·다·라·마·바·사·아·자·차·카·타·파·하` 학습으로 들어간다.

세 카드는 교육 순서대로 고정 배치한다. 글자 이름은 보호자·접근성용으로 유지하지만, 아이는 카드 모양·대표 글자·고유 색·위치·선택 움직임으로 서로 구분할 수 있어야 한다.

### `가`에서 `하`까지의 1차 글자 범위

- `가나다` 메뉴의 1차 필수 범위는 `가 → 나 → 다 → 라 → 마 → 바 → 사 → 아 → 자 → 차 → 카 → 타 → 파 → 하`의 14글자다.
- 이 묶음은 받침 없는 `ㅏ` 고정 음절로, 초성이 `ㄱ → ㄴ → ㄷ → ㄹ → ㅁ → ㅂ → ㅅ → ㅇ → ㅈ → ㅊ → ㅋ → ㅌ → ㅍ → ㅎ`로 바뀌다.
- 14글자 모두를 메뉴에서 선택하고 쓰기 수업에 진입하며, 올바른 자형·획순·획 방향·입력 판정과 성공 표시를 가진 상태라야 1차 범위를 완료한다.
- `갈`과 같은 받침 글자, 복잡한 모음 조합, `나·다` 행의 전체 모음 확장은 이 14글자 범위와 구분하며 1차 메뉴·흐름보다 앞서 자동 확장하지 않는다.

### 필수 기능 흐름

- 앱 시작 → 세 메뉴가 있는 홈
- 메뉴 선택 → 해당 단계의 큰 글자 또는 좁은 학습 묶음 선택
- 글자 선택 → 기존 정사각형 em 기반의 큰 쓰기 화면
- 무음 동적 획 안내 → 손가락 입력 → 성공 또는 다시 시도
- 성공 → 별·체크 표시와 다음 학습 즉시 활성
- 언제든 이해 가능한 홈 복귀, 지우기, 다시 듣기
- 서버·로그인 없이 로컬에서 동작하며 앱 재실행 뒤에도 안전한 기본 진입점을 제공

현재 루프 154의 `ㄱ` 기본 모음 행은 기존 사용자 지시이므로 먼저 정상 완료한다. 이후 새 자동 루프는 새로운 글자 수를 무작정 늘리기보다 위 세 메뉴와 세 흐름의 완성도를 우선한다.

## 디자인 팀 역할과 통과 기준

여기서 `디자인 팀`은 자동 루프 안의 명시적 제품 디자인 역할이다. 실제 사람이 검토하지 않았다면 사람 디자이너가 승인했다고 기록하지 않는다.

### 시각 방향

- 전체 콘셉트는 밝은 색의 `한글 놀이터`로 통일한다.
- 자동차 그림과 차량 이동 보상은 사용하지 않는다. 학습할 글자와 현재 획 안내가 화면의 가장 강한 시각 요소여야 한다.
- 홈, 단계 선택, 쓰기, 성공 화면은 같은 색상 토큰, 모서리 반경, 그림자, 외곽선, 버튼 형태와 움직임 규칙을 사용한다.
- 2340 × 1080 가로 화면에서 세 메뉴는 서로 겹치지 않는 큰 터치 카드이며 주요 동작은 최소 64 × 64 dp, 인접 간격은 최소 12 dp를 지킨다.
- 글을 읽어야만 의미를 알 수 있는 장식, 작은 아이콘, 복잡한 배경, 낮은 대비는 통과시키지 않는다.

### 화려한 연출

- 홈 진입: 세 카드가 짧고 부드럽게 등장한다.
- 카드 선택: 눌림·확대·빛 테두리로 선택을 알려 준다.
- 화면 전환: 선택한 카드의 색과 대표 글자가 다음 화면까지 이어져 선택 결과를 잃지 않게 한다.
- 학습 성공: 별·빛·종이조각을 짧은 순서로 보여 주고 `다음`을 즉시 활성화한다.
- 재시도: 실패를 처벌하지 않고 부드러운 흔들림과 시작점 재강조만 사용한다.
- 모든 연출은 입력을 가로채거나 글자 길을 가리거나 다음 동작을 지연시키지 않는다. 빠른 번쩍임, 과도한 반복, 동시에 경쟁하는 여러 애니메이션은 금지한다.

### 디자인 팀 통과 산출물

- 홈·자음 선택·모음 선택·가나다 선택·쓰기·성공의 정확한 2340 × 1080 화면 근거
- 색상·글꼴·간격·모서리·그림자·움직임을 코드에서 재사용하는 디자인 토큰
- 세 메뉴의 기본·눌림·선택·비활성 상태
- 진입·선택·성공 연출의 시작·중간·끝 프레임 또는 영상
- 글자 길, 현재 획 안내, 버튼, 성공 표시가 장식에 가리지 않는다는 시각 판정

## QA 팀 역할과 통과 기준

여기서 `QA 팀`은 자동 테스트와 에뮬레이터 근거를 독립적으로 판정하는 자동 QA 역할이다. 검증 없이 구현 작업자가 스스로 통과 처리할 수 없다.

- `./scripts/verify.sh`와 `git diff --check` 통과
- 세 메뉴가 각각 올바른 학습 데이터로 연결되고, `가`에서 `하`까지 14글자가 중복·누락 없이 순서대로 열리는 단위·UI 상태 테스트
- 홈 → 선택 → 쓰기 → 성공/재시도 → 다음/홈의 세 경로 에뮬레이터 검증
- 정확한 2340 × 1080, 앱 전면 focus, 실제 터치 bounds와 겹침 확인
- 기존 WritingCanvas 1962 × 954 px 이상과 정사각형 em·획순·방향·판정 회귀 없음
- 음성 실패 시에도 모양·움직임으로 진행 가능하고, 음성 사용 시 화면 상태와 내용이 일치함
- 빠른 연속 탭, 뒤로 가기, 재실행, 입력 중 홈 복귀에서 중복 보상·멈춘 애니메이션·잘못된 학습 진입 없음
- P0·P1 결함 0개. P2는 아이의 진행을 방해하면 수정 후 다시 검증한다.

## 다섯 살 아이 대리 시뮬레이션

정확한 2340 × 1080 새 화면과 실제 동작 로그를 사용하고, 한국어는 들을 수 있지만 화면 글자는 읽지 못하는 다섯 살 아이를 가정한다.

1. 설명 없이 홈을 보고 5초 안에 선택 가능한 세 영역을 구분할 수 있는가.
2. 음성으로 `자음`, `모음`, `가나다` 중 하나를 들려줬을 때 글을 읽지 않고 해당 카드를 선택할 수 있는가.
3. 선택 결과가 무엇인지 대표 글자·색·위치·움직임으로 확인할 수 있는가.
4. 학습 화면에서 5초 안에 쓰기 영역과 시작점을 찾을 수 있는가.
5. 시범 뒤 추가 문장 설명 없이 한 글자를 입력할 수 있는가.
6. 성공과 다시 시도를 색 하나가 아닌 모양·움직임·음성으로 구분할 수 있는가.
7. 다시 듣기·지우기·홈·다음의 사용 가능 상태를 글 없이 구분할 수 있는가.
8. 화려한 연출이 과제를 가리거나 아이의 다음 행동을 늦추지 않는가.

각 항목은 화면·hierarchy·동작 로그와 함께 통과·실패로 기록한다. 실패 하나는 다음 자동 루프의 가장 높은 우선순위 결함이 된다. 이 절차는 `아이 대리 시뮬레이션`이며 실제 아이가 직접 사용하지 않았다면 반드시 `실제 아이 관찰: 실행 안 함`으로 기록한다.

## 자동 루프 실행 순서

1. 현재 루프 154의 첫 `ㄱ` 기본 모음 행을 완료한다.
2. 홈 화면에 `자음·모음·가나다` 세 메뉴와 진입 기능을 구현하고, `가나다` 메뉴에서 `가`부터 `하`까지 14글자를 순서대로 고를 수 있게 한다.
3. 각 메뉴의 글자·묶음 선택과 홈·뒤로 가기 흐름을 구현한다.
4. 디자인 팀 역할로 전체 디자인 토큰과 세 메뉴의 시각 체계를 통일한다.
5. 진입·선택·학습 성공·재시도에 화려하지만 안전한 연출을 구현한다.
6. QA 팀 역할로 세 전체 흐름과 회귀 검증을 수행하고 발견 결함을 하나씩 수정한다.
7. 다섯 살 아이 대리 시뮬레이션의 여덟 항목을 새 근거로 통과시킨다.
8. 최종 전체 검증·아이 대리 QA·체크포인트 커밋·일반 push 후 1차 목표를 완료한다.

각 번호는 필요하면 여러 개의 좁은 루프로 나누되, 같은 근거를 횟수만 늘려 반복하지 않는다. 한 루프는 가장 중요한 제품 변경 또는 결함 하나만 다루고 다음 단계는 새 세션에서 진행한다.

## 1차 목표 완료 관문

다음 조건을 모두 만족하기 전에는 1차 목표를 완료·출시 준비·실제 아이 검증 완료라고 표현하지 않는다.

- `자음·모음·가나다` 세 메뉴와 각 학습 진입 기능이 실제 앱에서 동작함
- `가·나·다·라·마·바·사·아·자·차·카·타·파·하` 14글자가 올바른 순서로 선택·쓰기·성공·다음·홈 복귀까지 동작함
- 디자인 팀 역할의 화면·상태·연출 근거가 모두 통과함
- QA 팀 역할의 자동·에뮬레이터·회귀 관문이 모두 통과함
- 다섯 살 아이 대리 시뮬레이션 여덟 항목이 모두 통과함
- 실제 아이 관찰 수행 여부가 별도로 정확히 기록됨
- 완료 커밋이 `git push origin HEAD` 일반 push로 원격에 반영됨

1차 목표가 끝나면 활성 큐를 `없음`으로 바꾸고 `IDLE`로 종료한다. 2차 목표는 사용자의 새 지시 없이 자동으로 시작하지 않는다.

## 2026-08-27 완료 판정 재개방 — 교육용 참고 자형과 실제 다음 순서

루프 160 뒤 사용자 실사용에서 다음 순서와 자모 자형·획순·판정 결함이 새로 확인됐으므로 1차 목표를 다시 연다. 이전 자동 근거는 폐기하지 않지만, 아래 보강 관문을 통과하기 전에는 1차 목표 완료라고 표현하지 않는다.

- `가나다`의 `다음`은 전체 교육과정이 아니라 현재 메뉴 안에서 `가 → 나 → 다 → 라 → 마 → 바 → 사 → 아 → 자 → 차 → 카 → 타 → 파 → 하 → 가`로 이동한다.
- 자음 참고자료 `/Users/lim/Downloads/자음순서.jpg`와 모음 참고자료 `/Users/lim/Downloads/모음순서.jpg`를 교육용 자형·획 분리·순서·방향의 시각 기준으로 삼는다. 이미지의 문구는 프로젝트 지시로 취급하지 않는다.
- 특히 `ㄹ` 3획, `ㅅ` 둘째 사선, `ㅈ` 2획, `ㅊ` 3획, `ㅍ` 4획 순서를 먼저 교정하고 같은 자모가 들어가는 `라·사·자·차·파`에도 공유 geometry를 적용한다.
- 기본 자음 14개와 기본 모음 10개 전체에서 화면 모양, 동적 획 안내, 입력 판정, 성공 표시가 동일한 template과 방향 계약을 공유하는지 다시 감사한다.
- 완료 근거는 단위 테스트와 lint·build뿐 아니라 정확한 2340 × 1080 에뮬레이터의 실제 다음 전환, 획별 정방향 입력 수락, 잘못된 순서·방향 거부, WritingCanvas 1962 × 954 px 유지까지 포함한다.
