# LimDo 그래픽·시스템 루프 계약

## 목적

2차 제품 구현의 모든 UI를 자동 그래픽 디자인 역할과 함께 만들고, 필요한 자산을 Codex 내장 이미지 생성기로 자체 제작해 production에 적용한 뒤 실제 앱 화면에서 검토한다. 그래픽과 시스템이 모두 끝나면 새 최종 APK를 처음부터 끝까지 실제 조작하고 모든 고유 화면·중요 상태를 다시 캡처해 종합 판정한다.

`자동 그래픽 디자인 역할`, `자동 QA 역할`, `아이 대리 QA`는 서로 다른 검토 책임 이름이다. 실제 사람이 참여하지 않았다면 실제 그래픽 디자이너·QA 팀·아이의 검토나 승인으로 표현하지 않는다.

## 전체 단계

1. `그래픽·시스템 구현`: 2차 기획의 M1~M4와 발견된 시각 결함을 초점이 분명한 단일 루프로 구현한다.
2. `그래픽·시스템 완료 감사`: 화면 inventory와 기능 관문을 대조해 미구현·미검토 항목 0건을 확인한다.
3. `최종 전체 플레이`: 같은 최종 commit·APK로 모든 고유 화면과 중요 상태를 실제 사용자 입력으로 방문·캡처한다.
4. `종합 재검토`: 자동 그래픽 디자인·기능 QA·접근성·아이 대리 QA를 수행하고 중대 결함이 있으면 해당 결함 하나의 수정 루프로 돌아간다.
5. 새 P0·P1 0개, 진행 방해 P2 0개, 화면 누락 0건일 때만 최종 관문을 `통과`로 바꾸고 `IDLE`로 종료한다.

## 모든 시각 루프의 시작 관문

`.loop/state.md`에 다음을 기록한다.

- `단계: 그래픽·시스템 구현|그래픽·시스템 완료 감사|최종 전체 플레이`
- `시각 변경: 예|아니오`
- `자산 필요 판정: 필요 — 구체 근거|불필요 — 구체 근거`

시각 변경이 없더라도 `불필요`의 이유를 적는다. 시각 변경이 있으면 자동 그래픽 디자인 역할이 현재 production 화면과 기존 자산·색·모서리·그림자·아이콘 언어를 먼저 검토한다.

## 자산 필요 판정

다음 중 하나면 전용 bitmap 자산이 필요하다.

- 아이가 글을 읽지 않고 동작·상태·결과를 구분하려면 고유한 그림이 필요하다.
- 기존 코드 도형·문자·시스템 글리프로는 기기 간 동일한 실루엣과 그림체를 보장할 수 없다.
- 기존 production 자산을 안전하게 재사용할 수 없고 새 슬롯에 맞는 illustration·배경·particle이 필요하다.

다음이면 새 생성이 불필요하다.

- 기존 production atlas의 의미·해상도·alpha 여백·그림체가 새 위치에도 맞아 그대로 재사용할 수 있다.
- 단순 layout·간격·색 token·접근성 순서 교정으로 해결되며 새 raster가 과제를 더 명확하게 하지 않는다.

새 생성이 불필요하면 새 그림을 억지로 만들지 않는다. 기존 자산 재사용 역시 production 화면에서 크기·잘림·의미를 다시 검증한다.

## 자체 생성과 production 적용

자산이 필요하면 `imagegen` 스킬의 Codex 내장 이미지 생성기를 사용한다. 외부 이미지 API·API key·임시 emoji·시스템 글리프로 우회하지 않는다.

1. 사용 슬롯의 실제 px·dp, 배경색, 필요한 alpha, 시선 우선순위와 금지 요소를 먼저 측정한다.
2. prompt에 용도, 그림체, 조명, palette, 투명 배경, 구도, 글자·watermark 금지를 기록한다.
3. 생성 결과를 직접 열어 subject·형태·palette·투명도·잘림을 확인한다.
4. 선택한 결과만 project production 경로에 복사하고 prompt·원본·변환·최종 경로를 기록한다.
5. RGBA, 네 모서리 alpha, alpha bbox, 셀 경계, 투명 여백, 균일 배율과 target slot 안의 안전 여백을 자동 검사한다.
6. 실제 소비 코드·resource reference와 최종 APK 포함을 입증한다.

파일 생성만 완료로 보지 않는다.

사용자 선택을 받기 위한 D0 full-screen mock처럼 목표가 선택 전 production 적용을 명시적으로 금지하는 시안은 `자산 적용 범위: preview-only`로 분리할 수 있다. 이 예외는 목표 문서의 선택 관문, 실제 preview 경로와 규격, production `res`·소스·APK 미소비를 함께 입증할 때만 허용한다. 그 밖의 `자산 필요 판정: 필요`는 기본적으로 `자산 적용 범위: production`이며 production `res`, 소비 코드, APK 포함과 실제 화면 의무를 그대로 적용한다. preview 예외를 production 자산 완전성 관문 우회에 사용하지 않는다.

## 변경 전·후 실제 화면 검토

시각 변경 루프의 완료 근거는 모두 같은 화면 상태·2340 × 1080 앱 영역에서 수집한다.

- 변경 전 PNG와 hierarchy
- 변경 후 PNG와 hierarchy
- package·focus·물리 1080 × 2340·`user_rotation=1`
- APK SHA-256와 Git commit
- 자동 그래픽 디자인 역할 판정
- 자동 QA 역할 판정
- 글을 읽지 않는 다섯 살 관점의 아이 대리 QA

변경 전·후를 한 비교 입력으로 직접 보고 다음을 판정한다.

- 과제·다음 행동의 선명도
- 그림체·색·모서리·그림자·재질의 화면 간 일관성
- 글자 길·점선·시작점·버튼의 시선 경쟁과 가림
- 자산 왜곡·흐림·alpha halo·검은 배경·셀 번짐·잘림
- 주요 터치 크기와 상태·callback 보존
- motion 시작·중간·끝과 움직임 줄이기 안전성

## 만족과 반복 종료

`만족`은 주관적인 문구만으로 선언하지 않는다. 현재 루프 체크리스트가 전부 통과하고 새 P0·P1이 0개이며 학습·진행을 막는 P2가 0개일 때 통과한다.

실패하면 같은 결함에서 가장 중요한 원인 하나만 다음 반복에 고친다. 이미지 자체가 원인이면 단일 목표로 재생성하고, 배치·scale·crop이 원인이면 같은 자산의 표시만 조정한다. 수정 뒤 새 APK·새 화면으로 다시 비교한다. 단순히 반복 번호나 캡처 수만 늘리지 않으며 15회 중지 조건을 유지한다.

## 그래픽·시스템 완료 감사

2차 기획 M1~M4, 미해결 사용자 지시, QA finding, 현재 navigation destination과 고유 UI state를 inventory로 만든다. 다음이 0건일 때만 최종 전체 플레이 루프를 활성화한다.

- 미구현 사용자 기능
- 임시 placeholder·시스템 문자·불필요한 장식
- production에 연결되지 않은 생성 자산
- 실화면 근거가 없는 고유 화면·중요 상태
- 미해결 P0·P1과 진행 방해 P2

## 최종 전체 플레이

`docs/전체-플레이-QA-행렬.md`의 계약을 따른다. 과거 루프 캡처를 재사용하지 않고 새 최종 APK와 한 commit에서 전량 수집한다. 화면만 test hook으로 직접 열지 않고 홈부터 tap·draw·back·permission 응답·record·preview·delete·navigation 같은 실제 사용자 동작으로 진입한다.

동일 layout에 lesson 데이터만 바뀌는 화면도 전체 lesson의 실제 진입·정답·다음 mapping은 검증한다. 캡처는 교육 자형과 성공 화면이 다른 모든 lesson에서 수집하고, 완전히 동등한 공통 상태는 동등군과 대표 근거를 명시한다.

최종 종합 검토에서 실패하면 최종 관문을 `대기`로 되돌리고 가장 중요한 결함 하나의 수정 루프를 만든다. 수정 뒤에는 새 최종 APK로 전체 행렬을 처음부터 다시 수집한다.
